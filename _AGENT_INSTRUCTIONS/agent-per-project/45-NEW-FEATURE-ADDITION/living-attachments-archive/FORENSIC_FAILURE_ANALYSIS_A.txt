============================================================
SUGGESTED FIX DIRECTIONS
============================================================

1. FILENAME + FILE SIZE MATCHING (low risk):
   When path-tail matching fails, fall back to matching by
   (transfer_name + file_size_bytes). This would match 133484's
   "Following — Bluesky.png" (2,952,262 bytes) against backup copies.
   If exactly one backup file matches both filename AND size, use it.
   If multiple match (likely for identical screenshots), archive ALL
   copies — the content-addressable store deduplicates anyway.

2. SIZE-ONLY DEDUPLICATION FOR COMMON FILENAMES:
   When the filename has >1 backup hit, hash each candidate from the
   backup and check if any hash matches an un-archived attachment's
   file_size_bytes. Since the archive is content-addressed, even
   archiving the "wrong" copy (if file sizes match) produces the
   correct result if the files are byte-identical.

3. STRIP "at_0_" PREFIX FROM PATH-TAIL MATCHING:
   Before path-tail lookup, normalize GUID directories by stripping
   the "at_N_" prefix. This would make
   "08/at_0_E9F8AA4C-.../file.png" matchable against
   "08/E9F8AA4C-.../file.png" — but only if the backup also has the
   same base GUID (which it may not, as seen here).
