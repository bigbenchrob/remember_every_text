# Tweak SS setup files

## Prompt

```text
Refinement pass on the first source-scoped import proof slice.

Overall assessment:
The new incremental_update_ss/ architecture is much cleaner than the existing shadow pipeline and is heading in the correct direction.

Please make the following targeted refinements.

1. Remove UNIQUE(guid)

This is the most important correction.

Current schema still contains:

UNIQUE(guid)

This leaks the old single-source worldview into the new source-scoped architecture.

In the new model:

SourceScopedRowKey IS canonical row identity.

Therefore:

guid is metadata,
NOT canonical uniqueness.

Multiple sources may legitimately contain:

* identical Apple GUIDs
* overlapping histories
* restored backups
* migrated devices
* duplicate source occurrences

This must not violate canonical row identity.

Required change:

Replace:

UNIQUE(guid)

with:

CREATE INDEX idx_messages_guid ON messages(guid);

Keep:

UNIQUE(source_id, source_rowid)

because source-local row identity must remain unique per source.

2. Rename source_identity.dart

Current filename:

source_identity.dart

is now semantically overloaded because “source identity” has deep architectural meaning.

Rename to something more explicit, such as:

known_sources.dart

or:

source_registry_constants.dart

Use your judgment.

3. Keep import-ledger provenance

Keeping:

source_id
source_rowid

inside the import ledger is correct.

Do NOT remove them from the import DB.

(Working DB may later omit them.)

4. Preserve deterministic packing

The SourceScopedRowKey implementation looks correct.

Keep:

return (sourceId << sourceRowIdBits) | sourceRowId;

This is deterministic collision-free packing, not hashing.

5. Keep sender_handle_ss_id behavior

Current logic:

sender_handle_ss_id = pack(sourceId, handle_id)

is correct for now.

Do not redesign this yet.

Messages may reference handles before handle import exists. That is acceptable in the current proof stage.

6. Preserve ingestion normalization

Keep helper normalization behavior such as:

_boolInt()

The ingestion boundary is the correct place to normalize Apple schema weirdness.

7. Tests

Update/add focused tests for:

* duplicate GUIDs across different source_ids are allowed
* duplicate (source_id, source_rowid) remains forbidden
* guid index exists if practical to test
* existing packing/idempotence tests continue passing

Verification:

* dart analyze on changed files
* focused tests only

Response style:
Keep response under 12 lines.
Report only:

* files changed
* schema changes
* tests run
* blockers if any
```
