# Improve logging

## Prompt

```text
Task: Extend comparative validation to classify transient import catch-up lag as PHASE SKEW instead of durable MISMATCH

Context

The endurance polling log exposed an important comparison nuance.

Current behavior sometimes produces:

[comparison][incremental import]
MISMATCH:
  legacy=incremental import not required
  shadow=incremental import required

while the reason text simultaneously shows:

- production ledger already current
- shadow ledger still behind live source

Example observed runtime pattern:

legacyReason=ledger cursor and importable message count are current
liveMaxRowId=135989
importedMaxSourceRowId=135989

while shadow:
- ImportDecision.considerIncrementalImport
- rowIdDelta=2

This strongly suggests:
- production already completed import catch-up
- shadow is still in a valid transient import catch-up phase

This is analogous to the already-classified migration PHASE SKEW cases.

Goal

Extend comparative validation semantics so transient import catch-up lag is classified as:

PHASE SKEW

instead of:

MISMATCH

when the disagreement is causally explainable by asynchronous pipeline timing.

Architectural intent

The comparison layer should distinguish:

durable semantic disagreement
vs
temporally offset but causally explainable execution phases

The current migration comparison already does this correctly.

We now want equivalent semantics for import comparison.

Required behavior

Add import-phase-skew detection.

Example desired output:

[comparison][incremental import]
PHASE SKEW:
  legacy=incremental import not required
  shadow=incremental import required
  reason=shadow ledger lagging live source by 2 message(s); production ledger already caught up

Similarly, if the inverse transient state is observed:

legacy=incremental import required
shadow=incremental import not required

and production is still catching up while shadow already caught up,

that should also classify as:

PHASE SKEW

not MISMATCH.

Requirements

1. Extend comparison heuristics

Detect import-specific transient asynchronous skew conditions.

Likely signals:
- live source ahead of shadow ledger
- production ledger already current
- small explainable row-count delta
- transient execution window

2. Preserve durable mismatch semantics

Still classify as:
MISMATCH

when:
- there is no recognized transient explanation
- conclusions genuinely disagree
- facts are inconsistent in a non-transitional way

3. Keep architecture clean

Do not:
- add timing coordination
- synchronize pipelines
- add retries/debounce
- modify production behavior
- modify polling cadence
- add orchestration complexity

This is semantic classification refinement only.

4. Update focused tests

Extend:
incremental_update_comparison_integrator_test.dart

Add tests covering:

A.
legacy current
shadow import required
→ PHASE SKEW

B.
legacy import required
shadow current
→ PHASE SKEW

C.
true durable disagreement
→ still MISMATCH

5. Improve reason text

Reason text should explicitly explain:
- which side is lagging
- by how many messages
- why this is considered transient

Verification

Run:
- dart analyze on changed files
- focused comparison tests

Then rerun the endurance scenario:
- multiple bursts of messages across polling ticks

Confirm:
- transient import lag logs become PHASE SKEW
- durable disagreement still produces MISMATCH
- final steady state still returns MATCH / MATCH

Report:
- updated import phase-skew heuristics
- added/updated tests
- example runtime logs
- confirmation that production behavior remains unchanged
```
