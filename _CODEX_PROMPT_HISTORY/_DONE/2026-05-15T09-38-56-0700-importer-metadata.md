# Importer metadata

## Prompt

```text
Next architectural slice: introduce lightweight importer descriptors for the new importer-based shadow pipeline.

Context

The shadow incremental-update pilot is now functioning and validated with:

* shadow import
* shadow migration
* comparative validation
* endurance logging
* dev observability panel
* tick-event tracing

Recent completed work:

* added source_chat_rowid and source_sender_handle_rowid
* preserved source-scoped relationships in shadow import
* renamed ShadowMessageImportExecutor → ShadowMessageImporter

The importer abstraction is now real and should become the foundation for future prerequisite-bearing importers.

Goal

Introduce lightweight importer metadata WITHOUT changing runtime behavior.

This is NOT yet:

* importer graph execution
* topological sorting
* generic framework infrastructure
* production ownership
* dynamic importer registration

The goal is simply to establish a stable production-shaped metadata surface before additional importers are added.

Task

Create a minimal ImporterDescriptor model and attach it to ShadowMessageImporter.

Suggested shape

ImporterDescriptor:

* importerName
* sourceTables
* targetTables
* prerequisites
* continuationStrategy
* idempotenceStrategy
* validationStrategy

Keep this intentionally lightweight.

Strings/enums are acceptable for now.
Do not over-engineer.

Suggested location

lib/essentials/incremental_update/application/importers/

Possible files:

importer_descriptor.dart
importer_prerequisite.dart (only if truly useful)

Attach descriptor to importer

ShadowMessageImporter should expose something like:

static const descriptor = ImporterDescriptor(…)

or an equivalent lightweight getter.

Suggested descriptor contents

importerName:

* shadow_message_importer

sourceTables:

* message

targetTables:

* messages

prerequisites:

* empty for now

continuationStrategy:

* MAX(messages.source_rowid)

idempotenceStrategy:

* INSERT OR IGNORE / conflict ignore on already-imported rows

validationStrategy:

* cursor/count convergence validation

Important constraints

DO NOT:

* build importer graph orchestration
* implement topological sorting
* add runtime importer registries
* add dynamic discovery
* introduce production ownership
* change polling semantics
* change comparison semantics
* change endurance logging behavior
* change dev panel behavior

DO:

* preserve explicit architecture direction
* preserve importer/orchestrator separation
* preserve current tests and behavior
* keep metadata human-readable and causal

Tests

Add focused tests for:

* descriptor values are stable
* descriptor metadata is readable and intentional
* orchestrator still invokes importer exactly once
* no behavior change to current shadow flow

Architectural intent

This descriptor layer exists to prepare for future prerequisite-bearing importers such as:

* handles
* chats
* chat-handle joins
* attachments

without prematurely building a generic importer framework.

The system should remain:

* understandable
* explicit
* resumable
* causally traceable

Report back with:

* files changed
* final descriptor shape
* where descriptor lives
* whether any runtime behavior changed
* whether any future over-abstraction temptations were intentionally avoided
```
